# 花哪儿了 · 极简手机记账本

一款仿市面上主流记账 APP 的手机端记账应用。纯前端实现，**零依赖、离线可用、数据只存本机**。

额外支持**可选的 AI 增强**：填入你自己的 API Key，AI 会写更生动的每日 / 每月总结并自选图表；不填也完全能用。还支持**截图识图记账**（AI 视觉或本地 OCR 双引擎）、**账单导入**（微信 / 支付宝 / 工农中建交邮储等银行；CSV、xlsx、PDF 都能读，表头各异也能认）、**多账本**、**周期性自动记账**、**自定义分类**。

除了记账本身，还操心「钱够不够花、这笔值不值」：**今天还能花多少**、**上次花了多少**、**帮别人垫的钱要收回来**、**没花完的预算自动归仓**、**找出忘了关的自动续费**、**所有账本合并看板**、**外币账本**、**把钱换算成看得懂的东西**、**用真实余额反推漏记**、**想买先冷静 48 小时**。

## 一、怎么用（3 种方式，从简到全）

### 方式 1：直接双击打开（最简单，仅限电脑）
双击 `index.html` 即可在浏览器里使用。
> 缺点：`file://` 协议下 Service Worker 不生效，无法「添加到主屏幕」离线使用。
> ⚠️ **手机上不要这样打开**：文件管理器传给浏览器的是 `content://` 地址，页面脚本按相对路径加载不到，会卡在「正在准备你的账本…」。手机上请装 APK，或用 `手机安装.bat` 给的网址。

### 方式 2：装到手机上（推荐）⭐

双击 **`手机安装.bat`**，它会启动服务器并生成一个 **HTTPS 地址 + 二维码**。

```
  ✅  手机安装地址已就绪

  https://xxxxxxxx.tunnelmole.net

  ██████████████  ████  ██  ██  ██  ...
  ██          ██        ████████   ...
  （二维码）
```

**手机扫码或输入网址，就能真正安装成 APP：**

| 系统 | 步骤 |
|---|---|
| **Android / 鸿蒙** | 用 Chrome / Edge / 华为浏览器打开 → 等 1~2 秒 → 底部弹出「**安装应用**」→ 点它 → 桌面出现「花哪儿了」图标 |
| **iPhone / iPad** | **必须用 Safari** 打开 → 点底部**分享**按钮 → 「**添加到主屏幕**」 |

装好后是全屏运行、**断网也能记账**，数据存在手机本地。

> **为什么要 HTTPS？** 浏览器只在安全上下文里允许 Service Worker 和 PWA 安装。局域网 `http://192.168.x.x` 只能「加书签到桌面」，不是真安装 —— 图标会是浏览器样式、断网打不开。HTTPS 才能得到真正的 APP 体验。

> **这个地址是临时的，而且有限制——务必先读这段**
>
> - 关掉电脑上那个窗口，隧道就断了，域名随即注销。之后手机上再打开，只会看到一张「域名不存在」的错误页
> - **装在临时地址上的 App，数据也留在那个已经消失的域名下**，等于拿不回来。所以装完**第一时间去 设置 → 导出备份**
> - tunnelmole 匿名用户限制 **每小时 10 条隧道**，反复重启窗口会被限流
> - 想长期用，请先发布到一个**固定网址**（Cloudflare Pages 等），再用那个网址装一次
>
> **Service Worker 的兜底**：v1.8.1 起，页面导航会先校验返回内容里有没有 `assets/js/app.js` 这个标记。
> 所以域名停了之后，只要 App 之前成功打开过，仍然能从缓存里打开（离线可用）——
> 但拿不到更新，也导不出数据，这两件事都需要那个域名还活着。

#### 如果双击 bat 窗口闪一下就没了

Windows 的 `cmd.exe` 只认 **CRLF 换行 + 系统本地编码（GBK）** 的 bat 文件。
如果 bat 被编辑器存成 **LF 换行** 或 **UTF-8**，`if (...) else (...)` 这类多行块会被解析错，
脚本直接失败——而 `@echo off` 已经把回显关了，双击时就表现为「闪一下就没了」。

仓库里三个 bat 已统一成 **GBK + CRLF + 无 BOM**，并且：

- 中文提示用 GBK 输出（在 `chcp 936` 下正常显示）
- 调 node 之前临时 `chcp 65001`，让 `share.js` 的框线和二维码不乱码，跑完再 `chcp 936` 切回来
- 用 `goto :havenode` 代替嵌套 `if (...)` 块，避免老版本 cmd 的括号解析坑
- 找不到 Node.js 时**明确提示并 pause**，不会静默退出

#### 备选：仅同一 Wi-Fi 访问
双击 **`启动记账本.bat`**，终端会打印 `http://192.168.x.x:4173`。手机连同一 Wi-Fi 打开即可用（但只能加书签，不能真安装）。

> 需要 Node.js。如果没有，先装一个：https://nodejs.org

### 方式 3：部署到网上（想上传 / 分享给朋友）
整个目录是纯静态的，把这几个文件丢到任意静态托管即可：

```
index.html  manifest.webmanifest  sw.js
assets/  （整个目录）
```

- **Vercel / Netlify**：把文件夹直接拖进去，秒出公网地址
- **GitHub Pages**：推到仓库 → Settings → Pages → 选分支根目录
- **腾讯云 / 阿里云 OSS / COS**：开启静态网站托管，上传全部文件

> 部署后必须是 **HTTPS**，Service Worker 和「添加到主屏幕」才会生效。

## 二、功能清单

### 📝 视图记账
- 原生风格**数字键盘**，支持小数点、退格、`00` 快捷输入
- 内置**小计算器**：`100 + 50` 直接算出 150 再记账
- **16 个支出分类 + 6 个收入分类，共 90 个二级标签**（午餐 / 打车 / 话费…）
- 5 个账户（支付宝 / 微信 / 银行卡 / 现金 / 信用卡）
- 可补记过去任意日期的账
- **最近记录一键复用**：点一下就把那笔的金额、分类、账户填回来
- 点击任意账目可**编辑 / 复制 / 删除**，删除后 4 秒内可**撤销**

### 📅 自定义记账周期
四种周期模型，全部支持：

| 类型 | 说明 |
|---|---|
| 按月 | 可选每月起始日（1–28 日），比如设为 15 日就是「15 日 ~ 次月 14 日」 |
| 按周 | 可选周一或周日起算 |
| 双周 | 固定 14 天 |
| 自定义 | 任意天数（1–366），可指定锚点起始日 |

> 明细、预算、月度总结全部按你设定的周期统计，不是死板的自然月。

### 💰 自定义预算 + 低预算提醒
- **每周期总预算**，一键填入常用额度
- **分类预算**（餐饮 / 购物 / 交通…），支持「一键按比例分配」
- 进度条实时显示已用比例、剩余金额、**日均可用额度**
- **低预算提醒**：可多选阈值（50/60/70/80/90/100%）
  - 记账后自动弹窗提醒，**同一周期内不重复打扰**
  - 明细页顶部常驻警示横幅（黄色=接近，红色=超支）

### 📊 总结（日 / 月 / 年）
- **三个选项卡**：**日 / 月 / 年**，各看各的口径，翻页互不干扰
  - **日**：当天支出 / 收入 / 结余 / 笔数，按分类看当天钱花在哪
  - **月**：本月支出 / 收入 / 结余 / 笔数 / 日均，**环比上期涨跌**
  - **年**：全年支出 / 收入 / 结余 / 笔数 / 日均，**12 个月支出趋势柱状图**（自动标注花最多的月）
- **对比区间可以自己选**：点对比条 → 快捷项（昨天 / 上周同一天 / 上月同一天 / 去年同一天；上月 / 去年同月 / 前年同月；去年 / 前年 / 三年前）或**自己挑一个日期**
- 对比卡显示多花 / 少花多少，以及**分类维度的双条形对比**（一眼看出哪类花超了）
- **支出结构环形图** + 分类排行
- **自动生成的账本洞察**：最大支出、环比变化、最狠的一天、预算健康度、结余率…
- 预算执行卡只在「月」选项卡出现（预算是按周期算的）
- 一键导出 CSV / JSON，或复制文字总结分享

### 📒 多账本
- **日常 / 旅行 / 装修 / 副业**…想分几本分几本，各自独立的账目、预算、统计
- 记账页顶部有**账本切换条**（图标 + 名称 + 下拉），点一下就能换；右侧「+ 新账本」快速新建
- 每本账本可自定义**名称、图标（10 种）、主题色（8 种）**
- 设置 → 账本与自动化 → **多账本**：列表里能切换 / 编辑 / 删除，删除前会告诉你「这个账本里有 N 笔账目，会一起删除」
- 至少保留一本；账本之间的账目互不干扰（明细、总结、预算都只看当前账本）

### 🔁 周期性自动记账
- 房租、会员订阅、话费、房贷这类**固定支出，设一次就不用管了**
- 频率五选：**每月 / 每周 / 每两周 / 每季 / 每年**，可指定「每月几号」（1–28，避免月末缺失）
- 每次打开 APP 会**自动补记到期未记的期数**，补完弹一句「已自动记下 N 笔周期账目」
- **幂等保证**：每笔自动账目带 `rep:<规则id>:<日期>` 指纹，同一期只会生成一笔，**反复打开、跨设备同步都不会重复记**
- 漏了几个月也会**一次性补齐**（最多回溯 240 期），不会漏账
- 列表里能看到「下次什么时候记」「已经自动记了多少笔」

### 🏷 自定义分类
- 内置 **16 个支出分类 + 6 个收入分类（90 个二级标签）**，现在可以随意改
- **新增分类**：名称（8 字以内）+ 图标（22 种 emoji）+ 颜色（10 种）+ 二级标签（逗号分隔，最多 20 个）
- **改内置分类**：可以改名、换图标、改二级标签（存成「覆盖」，不动原始定义）
- **隐藏内置分类**：不想看到「旅行」就隐藏，可随时恢复；也有「恢复全部内置」
- **删除自定义分类**：已有账目会**自动归到「其他」**，不会丢账
- 二级标签跟着分类走，记账时的分类条和子标签行会自动同步

### 🎯 攒钱目标
- 自定义名称、图标、目标金额、目标日期、主题色
- **存入 / 取出**，每笔都有记录
- 进度条 + 完成百分比 + 还差多少
- 自动算出「每月需存多少」「还剩多少天」
- 达成时**庆祝动画**，可归档
- 按近期存入速度**预估达成时间**

### 👛 今天还能花多少
- 记账页键盘上方有一条**实时额度条**，一边输数字一边告诉你「记下后今天还剩 ¥X」
- 口径是**今天开始时剩下的额度 ÷ 剩余天数**，再减掉**今天已经花掉的**——不是简单 `剩余/天数`，所以花超了会立刻变红
- 三种状态：👛 正常 / ⚠️ 快用完（剩余不足 25%）/ 🚨 已超支
- 没设预算时不显示，不打扰

### ↺ 上次多少钱
- 选了分类，额度条右边就出现「上次 ¥25.80 · 2 天前」，点「填入」直接回填金额
- 按**分类 + 二级标签**分别记忆：选「餐饮 · 午餐」只看以前午餐的钱，不会混进晚餐
- 只在当前账本内比较（旅行账本的消费不会污染日常账本的价格记忆）
- 补记旧账也不会算错——内部按**时间戳排序**取最近一笔，而不是按录入顺序

### 💸 垫付待收（帮别人垫的钱）
- 记账时点「帮别人垫的」，填上**谁**和**还款日**，这笔就**照常记进账本**——钱确实先花出去了
- 账目上打一个「垫付 · 老王」标签，金额正常显示，不会因为你帮人垫钱就把账面做小
- **设了还款日的话，到期就会问你「老王 的钱还回来了吗？」**：
  - **已归还** → 记录**留在列表里划掉**，但从此**不计入任何金额**（支出、预算、今日额度、分类占比、对账全部跳过）
  - **还没还** → 推迟 3 天再问，不连环催
- **记账页顶部有常驻提醒条**：有没收回的垫付就一直挂着，「1 笔垫付到期了，该问问 老王、小李 · 共 2 笔 ¥1,100」，点「去收」直接打开垫付弹层——不用你记着
- 明细页顶部还有**待收回折叠卡**：合计金额、笔数、几笔已到还款日
- 「收回」是删除记录，所以**幂等**；编辑那笔账时勾掉垫付开关，就变回普通支出（不再计入待收）
- 设置 → 垫付待收：可以设**提前几天提醒催款**（当天 / 1 / 3 / 7 天前）

### 🔁 自动扣费提醒（找出忘了关的自动续费）
- **只找 App / 线上服务的自动扣费**：视频会员、网盘、云服务、软件订阅、AI 工具…
- **房租、话费、水电网、物业、加油、社保这类一律不进来**——它们是生活固定开销，不是「忘了关的续费」，去「固定月支出」里管
- 双重判定：① **像不像 App 扣费**（备注 / 子标签 / 分类里命中会员、订阅、云、视频、音乐、某 App 名等正向信号，且不命中房租话费等排除词）；② 同一商户归一化后出现 **≥3 次**、相邻间隔落在周期容差内（周 ±2 天 / 月 ±5 天 / 季 ±8 天 / 年 ±15 天）、金额在 **±5%** 内
- 列出每个扣费：周期、平均金额、已扣几次、累计花了多少、**下次预计扣款日**
- **提前 N 天提醒你**：设置里选「当天 / 1 / 3 / 7 天前」，到点提醒中心就会出现「「Netflix 会员」5 天后续费 —— 不想续的话提前去关掉自动续费」
- 三个处理方式：**已关掉续费**（不再提醒）/ **转成周期记账**（把这笔纳入自动记账）/ **下次再说**（按扣款日幂等延后）
- 也可以标记「不是订阅」手动排除
- **纯本地计算，不联网**

### 🏠 固定月支出（房租 / 话费 / 宽带）
- 设置 → 省钱与提醒 → **固定月支出**，专门放「每月固定、但不是 App 订阅」的钱
- 五个模板一键填：**房租 / 话费 / 宽带 / 水电燃气 / 保险**（会自动带上对应分类和默认日期）
- 填名称 + 金额 + 每月几号（1–28），之后**每个月到日子自动记一笔**，不用再手动记
- 本质是「每月一期的周期性记账」，所以和「周期性自动记账」共用同一套幂等保证（rep:<规则id>:<日期>，反复打开也不会重复记）
- 列表里能看到每项「每月几号 · 多少钱」，随时删除

### ↔ 所有账本（合并看板）
- 总结页有一张**「所有账本」**卡：每本账本的花费、占比条、合计
- 各账本按颜色堆叠成一条总占比条，一眼看出钱主要花在哪本上
- 点任意一行**直接切到那本账本**；点底部「只在这个视图里看全部合计」进入**合并视图**
- 合并视图下，明细 / 总结 / 图表都跨账本统计；此时记账会落到**第一本**（顶部账本选择器会标出来）
- 单本账本时不显示这张卡，不占地方

### 💱 外币账本
- 设置 → 账本币种：给任意账本单独设货币（**14 种**：USD / EUR / JPY / GBP / HKD / TWD / KRW / THB / SGD / AUD / CAD / MYR / RUB / CNY）
- 记账时**显示外币**（$ / € / ¥ / £…），键盘下方实时给出「≈ ¥710.00 · USD × 7.1」
- **入库一律存人民币**，所以预算、统计、图表、分类占比全都不受影响
- 汇率**手动填**（完全离线，不联网取汇率）；改了汇率只影响**之后**记的账，已记的不会被追溯改数
- 账目上同时保留原币金额与汇率，明细里能看到「USD 100.00」小标签

### 🧮 换算成实物
- 总结页有一张「这笔钱相当于」卡，把**本期总支出**换算成看得懂的东西
- 内置 **20 种等价物**：奶茶、咖啡、火锅、电影票、打车、机票、酒店、手机、笔记本、房租、健身房…
- 选品规则不是「除以第一个」，而是让**数量落在 1–20 的自然区间**（¥5000 不会说成「2777 杯奶茶」），并且**按分类优先匹配**（该说房租的时候不说奶茶）
- 如果这笔钱能对上某个**攒钱目标**，会多一行「这笔钱是「换新电脑」还差的 55%」
- 文案下面固定写一句「只是换算，不是说你花错了」——不做道德评判

### 🔍 余额反推对账
- 记账最容易错的不是算错，是**漏记**。这里用真实余额倒推漏了多少
- 填三样：**期初余额 + 期初日期 + 这个账户现在真实有多少钱**
- 算出：期初 + 期间收入 − 期间支出 = **账面应有**，再和真实余额比，得到差额
- 差额解读直接给结论：「实际比账面多 ¥128.00，大概率**漏记了支出**」/「少 ¥50，可能漏记了收入」
- 顺手列出**近 14 天里没有账目的日子**，那几天最可能漏记
- 只对比**单一账户**（支付宝 / 微信 / 银行卡 / 现金 / 信用卡），不会被现金、余额宝收益搅乱
- 记事表保留最近 50 次对账；未收回的垫付不算支出

### ⌨️ 键盘默认收起（不挡内容）
- 打开「记一笔」时**数字键盘默认是收起的**，整屏留给分类、子标签、成员和最近记录
- 底部只有一条常驻小条：「金额 · 点这里开始记」
- **点金额数字**（或点这条小条）→ 键盘从底部滑上来，同时下方露出「今天还能花 / 上次多少钱」

### 🛍️ 先别买（冷静期 + 忍住基金）
- 记账页输完金额，点「想买？先放着」，这笔就进**想买清单**而不是账本
- **冷静 N 小时**后再决定（预设 24 / 48 / 72 / 一周，可改）
- **清单里的东西会混进「明细」时间线里**，跟着日期排在一起，一眼看到「我最近想买什么」：
  - **冷静中** → 整行**标灰**，带「还有 1 天 23 小时 · 冷静期结束再决定」和一条冷静期进度条，金额前面加「≈」（还没真花）

    - 样本少于 3 次直接不说话（`return ''`），样本太少不下结论
- **我们走过的重要日子**（`renderDays`）：点「在一起 N 天」进时间轴，第一行是「在一起的第 1 天」（起点标），之后每个里程碑（100 / 200 / 300 / 365 / 520 / 730 / 1000 / 1314 天）各一行，**已过的显示「已过」并压暗，未来的显示「还有 N 天」**；日期由 `togetherSince + (N-1) 天` 算出，改资料里的日期会一起变
  - 这就是日历上那个 **★ 的全部口径**：只有上面这 8 个天数命中时才标。第 1 天不标 ★，它有自己的粉色「在一起」小字。日常日子不标 ★
- 两个子页都走 `page` 状态（`'home' | 'bill' | 'mode' | 'memories' | 'days' | 'report'`），和主页同级的 `try/catch` 兜底生效——任何一个子页抛错都会显示错误卡片 + 「重试」按钮，不会白屏
- 异地模式也能看日历，但「在一起第 N 天」只在同城露出
- **原来那张「我们存钱的证据」整页已经删掉**：日历上的 ❤️ 加上点开那天的存款流水，已经把这件事说清楚了，再单开一页是重复

#### 来自 TA 的偏爱
- 分类里新增**「红包」**（`id: 'redpacket'`，排在人之后、通讯之前）。图标是内联手绘：信封 + 袋口 + 封口横条，封口条中间裂开长出**两颗合成一颗的心**；用粉色 `#FF6A9B` 而不是正红——这个 App 里红色是「支出」的语义
- 一方记了一笔红包，另一方在首页「来自 TA 的偏爱」卡里会看到这一笔；卡上有收（+ 粉）有发（− 灰），底部一行「我发出去 ¥x」和「全部 ›」进完整清单
- **一条记录 + 一个 `rpFrom` 字段，不做两条账**：同一笔钱在一本账里只能花一次。做两条会让月汇总翻倍，退款、分类统计、合并看板都要各自处理重复
- 方向**只认 `rpFrom`**：`rpFrom === 'peer'` 是 TA 给我的，`rpFrom === 'me'` 是我发给 TA 的；「一起花」「互相请」不算红包方向
- **手动补记**：首页卡片「全部 ›」进独立偏爱页，右上角「+ 补记」→ 选方向、金额、日期、备注。走 `S.cpAddFavor()`（TA→我）或 `S.cpAddTx({ catId: RP_CAT, rpFrom:'me' })`（我→TA），和自动识别的是同一条账，不会多算一份支出
- 选红包时，记账弹层的归属提示会变成粉色：「这一笔会出现在 TA 的「来自 TA 的偏爱」里 💗」
- 没有红包时整张卡不渲染，不在首页留一个空壳

#### 关掉之后能重新打开
- 关掉情侣账单**只是关开关**：账目、金库、资料、印记全部原样留着
- 再次进情侣栏时，如果资料还在，首页顶部会多一张「上次的情侣账本还在」的卡片，写明和谁的那本账还留着，点「重新打开」一步回到主界面，**不用重走同意流程**
- 之前有个坑：关闭后 `step` 会停在 `'mode'`，再进来直接跳到同城/异地选择页，看起来像被要求重填。现在资料齐全时强制停在起手页

#### 关闭 / 历史账本 / 彻底删除
- 首页底部只有两行：一行是「切换同城 / 异地」+「关闭账本」两个并排按钮，下面一行是**一行很小很淡的字「历史账本（N）」**
  - 用户的原话是「历史账本要稍微隐秘一点」：字号比正常按钮小、`opacity` 压到 0.78、还是下划线文字链，不主动出现在视线中心
  - `_test/verify-couple.js` 里有一条断言专门盯这个：历史账本入口的 `opacity < 0.9` 且字号小于「关闭账本」按钮
- **只有走过「关闭账本」，这本才会进历史账本**。当前正在用的那本永远不列在里面——`openBooksList()` 用 `S.cpBooks().filter(b => b.id !== currentId)` 过滤
  - 空的时候写「当前这本在用，还没有别的历史账本」或「还没有历史账本」+ 小字「关掉一本账本后，它会收进这里」
- **关闭账本**（`S.closeCouple(reason)`）：走四屏——先问要不要再想想 → 选一个原因（我们吵架了想静一静 / 我们分开了 / 我们现在不一起记了 / 想换一本新的 / 其他，可以跳过）→ 确认页写明「7 天内点一下就能恢复」→ 完成后给两个出口（回到首页 / 重新打开），底部还有一行淡字「不再需要它了」
  - 关闭后 7 天内（`S.cpCanUndo()`）恢复按钮写的是「撤销关闭」，直接 `S.openCpBook(id)` 把 `status` 从 `'closed'` 改回 `'active'`、`closedAt` 清零、`enabled` 置真
  - 超过 7 天也能恢复，只是入口变成「重新打开」，不再是「撤销」
  - 全程不用红色、不用感叹号、不摆「我见证了你们 XX 天」这种数字劝留——App 没资格当见证者
- **历史账本页**：每行一个 `.cpb-item`，左边 `[data-book]` 点一下就用 `S.openCpBook(id)` 把那一本重新打开，右边一个 `.cpb-del` 「删除」
- **彻底删除**（`S.wipeCpBook(id)`）两关，从历史账本那一行进去：
  - 第一关「彻底删除这一本？」主按钮是「先不删」，次按钮才是 `.btn--danger` 的「删除」
  - 第二关要**照着输入「删除」两个字**才点得动红按钮（不用勾选框——勾选会变肌肉记忆，打字不会）
  - 删的是这一本的账目、这一本的基金、`cpBooks` 里这一条、这一本的订阅识别记录；删完只说一句「删掉了。」
  - **这是整个情侣账本里唯一一处允许出现红色的地方**
- 关闭与删除都不碰个人账本：`state.tx` 与 `state.cpTxs` 从头到尾是两套数组
- **原来「从首页收起」已经删掉**：底栏那颗心点一下就变淡的「收起」在语义上和关闭打架，用户根本分不清「收起了」和「关掉了」，还会以为数据没了。想藏就不记，不需要一个中间态

#### 多本情侣账本
- **「换一本新的」搬到历史账本页里**（首页不再有）：它调 `S.startNewCpBook()`，老账本 `status` 转 `'closed'`，新账本 id 是 `'cp'+order`，`settings.couple` 里的资料字段重置，`activeId` 指向新本
- `cpTxs` 里每一笔都带 `cpBookId`，`S.cpTxs()` **只返回当前这一本的**，`S.cpTxsOf(id)` 拿任意一本；基金同理（`goalBySlot` 也按 `cpBookId === cpActiveId()` 过滤）
- **写数据的路径必须走 `cpWriteId()`**，不能直接读 `settings.couple.activeId`——否则换个账本就会把账记到上一本里去
- 迁移：老数据没有 `cpBooks` 时，只要「有情侣账目 / 有情侣基金 / `enabled` 为真 / 资料填过」任一成立就补一本 `cp1`，并把所有 `cpTxs` 和 `kind === 'couple'` 的目标都盖上 `cpBookId`

#### 双人同步（`assets/js/couple-sync.js`）
- 真引擎：配对串（16 字节 room + 16 字节 secret）→ HKDF-SHA256 派生两把钥匙 → 客户端 AES-GCM 加密；服务端只存「房间号 + 密文 + 序号」，作者也看不到明文
- 对外只有 `pair/join/leave/outboxPush/outboxFlush/pullSince/syncOnce/hook/status`；`store.js` 在 `emit()` 之后调 `hook()`，整段 `try/catch` —— **同步坏了不影响记账**
- 节奏：打开 App、记完一笔（800ms 防抖）、回到前台或联网立刻、前台每 20 秒一次。**不做实时推送**：浏览器关掉就收不到，ntfy 那套要装第二个 App 才能后台提醒，为此加一条第三方数据流不值得
- 拉到对方新记的账时抛 `couple:peer-tx` 事件，情侣主页在头部下面贴一条「**TA 刚记了 N 笔 · 去看看**」，点进账单页就清零。不做成 toast：这是「你不在的时候」发生的事，2.2 秒会错过
- `txNew` 只数**对方真新增**的账：自己推上去又被自己拉回来的 op 靠实体上的 `_seq` 回填挡掉，改一笔 / 删一笔都不算「刚记了」
- **同步完自动重画**：`applyRemoteOps` 只改数据不碰 DOM，所以 `store` 会 `emit({action:'remote'})`，`app.js` 订阅到、且当前正看着情侣页时调 `ViewCouple.softRefresh()`（120ms 合并三次 emit、有弹层时不打断、保持滚动位置）。没有这一步，对方记的账要手动刷新页面才出现
- **APK 内直接下载新包**（v1.18.8 起）：壳里注入了 `JZApp.downloadApk()`（`MainActivity.UpdateBridge`），页面用 `App.openApkDownload()` 调它走系统下载器，完成后通知栏点一下安装；网页版 / 老 APK 没有桥，自动退回浏览器。桥只接受 `https://where-i-paid.pages.dev/download/*.apk`
- **APK 里接口必须走绝对地址**：安卓壳加载的是本地资源，origin 是 `https://appassets.androidplatform.net`，相对路径 `/api/couple/*` 会打到本地资源加载器上永远 404（真机表现就是「配对一直连不上服务器」）。`couple-sync.js` 的 `apiBaseFor()` 负责这件事，同时 `functions/api/couple/_middleware.js` 给这个 origin 放行 CORS + OPTIONS 预检（带 `x-couple-auth` 的自定义头必然触发预检）
### ⚙️ 其他
- **浅色 / 深色 / 跟随系统**三种主题
- **数据备份**：导出 JSON 完整备份、导入恢复（合并 / 覆盖两种模式）
- **CSV 导出**：Excel / WPS 直接打开

## 二·五、发布到网上 & 版本更新

### 源码与安装包

仓库地址：**<https://github.com/ZwZ-1206/where-i-paid>**

| 想干什么 | 去哪儿 |
| --- | --- |
| 直接装到安卓手机 | **官网 <https://where-i-paid.pages.dev/>** → 「下载 APK」（国内能开；GitHub 只作备份） |
| 看源码 / 提 issue | 仓库根目录，`assets/js/` 是全部前端逻辑，`_test/` 是自动化测试 |
| 只想要网页版 | clone 下来双击 `index.html`，或跑 `node build-dist.js` 发布 `dist/` |

> APK 从 v1.18.7 起由官网自己托管（`site/download/whereipaid-v<版本>.apk`），
> `build-site.js` 会把 `dist-apk/` 里同版本的包拷过去，并把首页的下载按钮指向它。
> 版本清单 `site/app/version.json` 里同时写入 `apk` 字段，App 的「检查更新」据此直接给官网地址。
> GitHub Releases 仍然同步留着，作为备用通道（国内经常打不开，所以不再当主路径）。

### 一键打包（推荐先做这一步）

双击仓库里的 **`打包发布.bat`**（或 `node build-dist.js`），会把**真正要发布的 35 个文件**复制到 `dist\`，
并顺手校验 `sw.js` 的版本号和 `index.html` 里所有 `?v=` 是否一致。

> **不要直接把整个项目文件夹拖到托管平台。** 项目里 `_test/` 目录跑完会留浏览器 profile 和截图，
> 而真正要发布的只有 **约 1.3 MB / 35 个文件**。

### 放到网上（三选一）

| 方式 | 要不要备案 | 说明 |
| --- | --- | --- |
| **Cloudflare Pages / Vercel / Netlify**（推荐先试） | **不需要** | 把整个文件夹拖进去，几十秒出网址，免费、自动 HTTPS。服务器在境外，所以不用工信部 ICP 备案。缺点：国内访问偶尔慢 |
| **阿里云 OSS / 腾讯云 COS + CDN** | **必须要** | 用自己域名 + 国内节点就得域名 ICP 备案（个人也能备，7–20 个工作日）。不备案用国内节点会被拦 |
| **只给自己用** | **不需要** | 仓库里的「启动记账本.bat」，同一 Wi-Fi 下手机直接打开 |

> **备案跟「服务器在哪」绑定，跟「谁做的」无关。** 服务器在境外 → 不需要 ICP 备案；服务器在国内 → 域名必须备案。
> 本 App **纯网页 + 不收集任何用户信息**（数据全在用户浏览器的 localStorage 里），所以不涉及个人信息保护、等保、公安联网备案这些。
> 只有当你**打包成安卓 App 上架应用商店**，才需要额外做「App 备案」和应用签名。

### 手机下载会不会报毒

- **通过浏览器打开网址 → 添加到主屏幕（PWA）**：本质还是网页，**没有安装包，不会被杀毒软件报毒**，这是最省事的路径
- **打包成 `.apk` 分发**：才会有这个问题。个人签名的新包容易被国产厂商的「纯净模式」拦一下（提示「未知来源」「疑似风险应用」），正规做法是走正规签名 + 上架应用商店

### 以后怎么发新版（关键两步）

1. 把 `sw.js` 里的 `const CACHE = 'jizhang-vX.Y.Z';` 改成新版本号
2. 把 `index.html` 里**所有** `?v=X.Y.Z` 也改成同一个号
3. 把文件传到服务器覆盖旧的
4. 用户下次打开 App 会自动拿到新版；也可以在 **设置 → 关于 → 检查更新** 手动点一下

**为什么这两步必须做**：Service Worker 会把旧文件缓存在用户手机里，只有缓存名（版本号）变了，浏览器才知道「该换新的了」。不改版本号，用户可能几天都看到旧界面。

### 版本更新怎么工作

- `sw.js` 里的 `CACHE` 名就是版本号，既是本地缓存的 key，也是「服务器上是哪一版」的判据
- **每次启动自动核对一次**：启动 3.5 秒后悄悄拉一次 `sw.js`，版本不一致就在底部弹一条「发现新版本 vX.Y.Z · 当前 vA.B.C」+「更新 / 以后」——不打断使用，30 秒自己收起
- **设置 → 关于 → 检查更新** 也可以手动点：`fetch('sw.js?t=...', {cache:'no-store'})` 读服务器上的 `CACHE` → 和本地 `caches.keys()` 里的名字比
- 不一样就 `registration.update()`；手动那条会弹窗问「发现新版本，现在更新？」，自动那条直接给底部提示条
- 确认后等新 worker 接管（`controllerchange`，最多等 1.5 秒）再 `location.reload()`
- **更新只覆盖程序文件，不碰 localStorage**（键名 `jizhang.v1`），所以账目不会丢

## 三、数据说明

- 个人账本、目标、设置、订阅等全部保存在**浏览器 localStorage**（键名 `jizhang.v1`），**不上传**
- 情侣账目单独住在 `state.cpTxs`；**开启双人同步后，只有这一部分会同步到 Cloudflare**（端到端加密，服务器只存密文），其余数据一个字节都不传
- 换手机 / 换浏览器请先「设置 → 导出备份」，在新设备「导入备份」
- 清理浏览器数据会丢失账本，记得定期备份

## 五、技术要点

- **零运行时依赖**：没有 React / Vue / 任何 npm 包，打开就能跑
- **金额用「分」存储**（整数），杜绝浮点误差
- **图表纯手写 SVG**，无 Chart.js 之类的大依赖，包体极小
- **响应式**：手机上全屏，电脑上居中显示为手机比例
- **PWA**：可安装、可离线、有快捷方式（记一笔 / 总结 / 目标）
- **手机安装**：内置 HTTPS 隧道（tunnelmole），把本地服务映射到公网，满足浏览器的安装条件
- **暖心提示默认不用 AI**：16 条判断规则 + 88 句中文文案，FNV-1a 哈希按日期选句，全在本地跑，零延迟零成本
- **AI 是可选的加法，不是地基**：所有功能在不填 Key 的情况下完整可用；填了之后只是让文字更生动、多一张自选图表
- **AI 走浏览器直连**：没有后端、没有代理，Key 存在本地，请求直接发给你选的服务商（已实测通义/Kimi/智谱/硅基流动的 CORS 都允许）
- **识图双引擎**：AI 视觉按量计费更准；本地 OCR 用 tesseract.js，免费且图片不出设备
- **AI 输出结构化 JSON**：花括号配对解析（能跳过字符串内的括号与转义），解析失败会明确报错而不是静默降级
- **账单 CSV 是「准实时」的合规解法**：微信/支付宝/银行都没有面向个人的开放接口，实时监控必须与厂商合作（要营业执照 / 企业资质）。CSV 导入零合作、完全合规，覆盖三家
- **账单解析不靠固定列序**：按列名关键词识别（表头可能在第 6 行之后），金额支持 `¥1,234.56` / `-88.00` / `(100.00)` 三种写法，编码自动识别 UTF-8 / UTF-16 / GBK
- **重复导入靠指纹去重**：`srcKey = FNV1a(平台|时间|金额|单号或商户)`，同一份账单导多少次都只进一次
- **跨月账单按真实日期入库**：不按导入时间戳，弹层按月分组预览、已记过的月份标「已有记录」，账本里有空洞会主动提醒补账
- **多账本靠 `bookId` 隔离**：账目 / 周期规则都带账本归属，统计、预算、明细全部只看当前账本；删账本前会告诉你有多少笔会一起删
- **周期记账是幂等的**：每期生成 `srcKey = rep:<规则id>:<日期>`，跑多少次都只记一笔；月末用 `U.daysInMonth` 钳制（每月 31 日不会在 2 月丢账）
- **总结页三种口径独立**：日 / 月 / 年各用各的 key（`D:2026-03-09` / `CAL:2026-03` / `Y:2026`），翻页不串味
- **自定义分类是「覆盖」而非「改写」**：内置分类改名/隐藏都存成 overrides / hidden，原始定义永远在，历史账目始终能解析出名字；删自定义分类时账目自动归到「其他」，不丢账
- **「今天还能花」不能用 `剩余 / 天数`**：那个数会随今天的花费一起缩小，导致「我今天额度已经花完了，它还在显示能花 200」。正确口径是**今天开始时剩下的额度 ÷ 剩余天数 − 今天已花**
- **「上次多少钱」必须按时间戳排序**：`state.tx` 是**录入顺序**，补记旧账会打乱它；所以先全量匹配再 `sort(ts desc)`，不能边倒序扫边提前退出
- **垫付两段语义**：**没还的时候照常入账**（钱确实先花出去了，只额外打 `pending` 标）；**还回来之后只留档**——`isVoid(t)` 判定 `advance.status === 'settled'`，`summary / budgetStatus / todayQuota / dailySeries / reconcile` 全部跳过它。所以列表里还能看到「老王 · ¥300 · 划掉」，但一分钱都不进统计
- **余钱归仓靠 `srcKey` 幂等**：每个已结束周期记 `save:<周期key>`，存在目标的 `logs` 里（不是账目表），所以反复启动、反复打开设置都只归仓一次
- **长截屏 OCR 必须按宽度缩放、按高度切片**：早期用「最长边 1400」等比缩，1080×6000 的长图会被压成 252 宽，字全糊——这是「长截屏识别不准」的根因。现在 `planTiles()` 只限制**宽度**（上限 1600，不足 900 就放大），高度不动，超过 2.2 倍高宽比就横切，每片 1400 高、相邻重叠 90px（重叠保证不会把一行字切成两半），单片走 PSM 4（假定单列、字号有变化），最多 14 片。重叠会带来边界重复行，`parseList()` 用「最近两行同名同额」去重
- **列表 vs 详情要分流**：账单列表截图里可能既有每笔明细又有底部「合计」，所以不能一见到金额就当总额。`parse()` 的判据是：能拆出 ≥3 笔 → 列表模式（哪怕有合计行，合计会被 `SUMMARY_LINE` 挡掉）；只有 1 笔且文本里有「实付/支付金额」这类强标记 → 详情模式
- **自动扣费识别要看「像不像 App」**：只靠「周期 + 等额」会把房租、话费、水电一起抓进来（它们才是最规律的扣款）。所以先过一道 `isAutoDebit`：正向信号（会员 / 订阅 / 云 / 视频 / 具体 App 名）命中、且排除词（房租 / 话费 / 水电网 / 物业 / 加油 / 社保…）不命中，再谈周期和金额。排除词里不能写太短的片段——`et` 会把 `netflix` 一起干掉
- **生活固定开销走单独入口**：房租 / 话费 / 宽带不是「忘了关的续费」，硬塞进订阅提醒只会变成噪音。它们本质是「每月一期」，所以「固定月支出」只是 `addRepeat` 的一层预设外壳，幂等和补记直接复用周期记账那套
- **清单条目要混进时间线**：`wishesIn(period)` 返回 cooling / ready / dropped 三态并带上 `leftMs`，已买的直接不进时间线（否则和它生成的那笔账目重复）。明细页把账目和愿望合成一个 `rows` 数组按 `ts` 排序后再按日分组，所以两种行天然交织在正确日期下
- **外币只换「显示」，不换「存储」**：`amount` 永远是人民币分，原币金额和汇率存在 `amountFx / fxRate / fxCode`。这样预算、统计、合并看板、图表都不用改，改汇率也不会污染历史账目
- **换算实物要选品，不能只做除法**：给每个候选按「数量离 1–20 有多远」打分（`|log(count)|`），分类匹配的再减 0.8 分。否则 ¥5000 会被说成「2777 杯奶茶」
- **合并视图是个虚拟账本**：`activeId === '*'` 时 `activeBook()` 返回一个不落库的虚拟账本，`txIn()` 跨账本读取，但 `writeBookId()` 仍落到第一本——**读跨账本、写不跨账本**
- **提醒都带「处理完就消失」的出口**：订阅可「已关掉 / 转周期记账 / 下次再说」，垫付可「已收回 / 再等 3 天」，愿望可「还是买了 / 算了」。不做只能看不能消的提醒
- **情侣账单不挂账本**：它存在与 `state.tx` 并列的 `state.cpTxs` 里。如果做成 `kind: 'couple'` 的账本，`bookPicker / txIn / 明细 / 合并看板` 必然能看到它——而用户的原始要求是「记一笔完全属于个人账本，情侣账单全部页面只在情侣栏」。迁移时老的 `kind: 'couple'` 账本会被搬进 `cpTxs`，账本本身删除
- **情侣子页也走 `page` 状态**：`'home' | 'bill' | 'mode' | 'memories' | 'days'` 是平级的，不是引导流程的 `step`。之前「切换同城/异地」被写成 `step = 'mode'`，而 `on()` 为真时 `render()` 根本不看 `step`，用户看到的就是「被踢回引导流程，像是要重填资料」
- **同步用「钩子 + 空实现」隔离**：`store.js` 的 `syncHook()` 在 `cpAddTx / cpUpdateTx / cpRemoveTx` 之后各调一次 `CoupleSync.hook()`，整段 `try/catch` 吞掉。第二阶段填实现时不用回头改数据层，而现在离线行为一个字节都不变
- **日期选择器是三层网格，不是翻 12 次年**：标题上的「年」「月」都能点。点「月」进 12 宫格月份、点「年」进 12 宫格年份（一次跨一年），选完自动退回下一层。原来只有左右翻月，从 2026 翻到 2023 要点 36 下。底部「今天」按钮已去掉，「确定」改成一个右下角的胶囊气泡（`position:absolute; right:16px; bottom:14px`），另加一块 `.dp-pad` 占位防止遮住最后一排日期
- **`datePicker` 同时支持 `min` 和 `max`，两端都夹**：以前只有 `max`，选「下次见面」这种未来日期时过去的日期画成灰色却照样能点。现在 `opts.min` 与 `opts.max` 都先过 `asTs()`（数字 / `Date` / `'2026-10-18'` 字符串统一处理，`new Date(ymd)` 在部分环境会得到 `NaN`），再各自 `startOfDay`；越界的日格加 `.dp-day.off`（变淡 + 删除线 + `pointer-events:none`），年/月格里整页越界的同样 `.off` 且点不动。`onPick` 返回前还会 `clampTs()` 夹一次，防止靠键盘或脚本绕过
- **「下次见面」连几点一起定**：`datePicker` 新增 `opts.time`，日历下方是一颗 `.dp-blob` 气泡显示当前时刻，点开在下面铺 24 个小时格 + 12 个分钟格（5 分钟一档），旁边还有 `08:00 / 12:00 / 18:00 / 20:00` 四个快捷胶囊。`onPick` 把 `h:m` 叠到当天 0 点上再返回；不带 `opts.time` 的调用行为不变（仍返回当天 0 点）。**没有用原生 `<select>`**：它在手机上弹出来还是系统那套老方框，跟整个 App 的胶囊气泡完全不搭，所以宁可自己画。存储格式升级为 `'YYYY-MM-DD HH:MM'`，但 `parseMeet()` 兼容老数据（只有日期时 `hasTime=false`，界面不写几点、倒计时按当天 14:00 兜底），所以老账本不会被新字段弄崩。倒计时改按小时算（`Math.ceil(diff/3600000)`），卡片多一行 `.cp-mod-time` 写出「2026年11月1日 20:30」
- **`opts.hideTip` 关掉日历提示行**：`.dp-tip` 在有 `min`/`max` 时本来会写「只能选今天…」，而灰格子加删除线已经说明了同一件事，重复一遍反而挤。注意 `hideTip` 时 `elTip` 为 `null`，提示那整段必须包在 `if (elTip)` 里
- **攒满见面基金才问一次**：`checkMeetFundFull(beforeSaved, goalId)` 拿「刚才那次操作之前」的已存金额做判断——只有 `beforeSaved < target && saved >= target` 才弹，否则存进去之后每笔都会再问一遍。目标先按 `coupleMeetFund()`（`slot:'meet'`）找，找不到再退回用户刚才实际存的那笔（`goalId`），因为用户完全可能把目标定在小金库上。选「重新定个目标」走 `updateGoal(g.id, { saved: 0, target: 0 })`（`logs` 不动，流水留档）再以 `openVaultSheet(g, { askTarget: true })` 直接接上定目标面板
- **存取面板里改钱，外面的卡片要跟着重画**：`submit()` 原来只 `renderBody(body)` 重画弹层内部，关掉弹层回首页还停在存档时的进度，得刷新整页才更新。现在补一句 `const host = document.querySelector('#view-couple'); if (host) render(host);`（包在 try 里）。没设目标时 `.cp-vault-cap` 也不再死写 `0%`，改成「已经攒了 ¥X · 还没设目标，去定一个吧」——钱明明存进去了，百分比却永远是 0，看起来像没存上
- **「发现新版本」气泡的两个坑**：①它挂在 `.toast-host` 里，而那个容器是 `pointer-events: none`（为了 toast 不挡住页面），横幅没显式写 `pointer-events: auto` 的话，整条连同「更新 / 以后」两个按钮都是点了没反应——`elementFromPoint` 在这块区域直接返回 `null`。②原来用 `left: 16px; right: 16px` 定位，手机上看着正常，电脑上就被拉成横贯 1400px 的一整条。现在改成 `left: 50%` + `translateX(-50%)` + `width: min(calc(100vw - 32px), 420px)`，宽屏走同一条居中的底栏；`.in` 的入场动画也因为 transform 被占用了而改成 `translate(-50%, 0)`
- **日期选择器默认停在「本月」，不是停在选中日所在月**：选未来日期时打开就能看见今天及以后；顶部 `.dp-tip` 直接写明「只能选今天（10月18日）以后的日期，最远到 10月18日」。`<body>` 上挂了 `data-dp-min / data-dp-max / data-dp-today / data-dp-sel / data-dp-view` 五个探针属性，出问题时一眼看出是解析炸了还是渲染炸了
- **输入框的「大黑框」是浏览器 UA 的 focus ring**：`index.html` 头部内联一段 `<style>`（必须在两个 `<link>` 之后，否则被覆盖）先 `*:focus, *:focus-visible { outline: none !important }` 全部清掉，再用 `box-shadow: 0 0 0 2px var(--brand-soft)` 给 `input/textarea` 做一版浅蓝光环。键盘用户仍有可见焦点，鼠标/手指点进去不再出现黑色方框
- **`.btn:disabled` 全局真灰**：`app.css:953` 后统一 `background:var(--bg-2); color:var(--text-3); box-shadow:none; pointer-events:none`。此前 `.btn` 完全没有 `:disabled` 样式，主色按钮 disabled 时仍是满血蓝，看着能点却点不动
- **小金库的「两颗心」是进度条**：`--gap = 124 × (1 − 存款比例)`，0% 相距 124px、50% 62px、100% 合成一颗 `.cp-heart--big`。存满时那两颗旧心**不渲染**（不是留着空壳），卡片下一行 `.cp-vault-cap` 写「两颗心靠拢了 37% · 还差 ¥3,140.00 就合上」
- **小金库目标金额的入口在存取面板第二行**：`.cv-target-row` 整行可点 → `openTargetSheet()`，快捷金额 `[data-qk]` 四档，留空或 0 表示不设目标（`S.updateGoal(id, { target: 0 })`）。此前目标只能在新建时设，进去就改不了
- **`UI.confirm` 的 `single` 模式**：`opts.single === true` 或 `cancelText === okText` 时只渲染一个按钮（`.modal-btns--one`，宽度 100%、高 46px、圆角 23px），并真的把 `[data-act="cancel"]` 从 DOM 移除而不是隐藏。所有「只在本机」这类告知型弹窗靠它统一，不再出现两个一模一样的「知道了」
- **「TA 那边现在几点」不能猜时区**：不开同步时两台手机之间什么都读不到，所以 `peerClock()` 不自己推断，而是由用户选一次 `settings.couple.tzOffset`（`setCoupleConfig`），卡片上直接标出依据「UTC−5 · 比你快 13 小时」。没设时区时显示 `--:--` + 「还没设时区」+「选 TA 的时区」，绝不假装知道
- **模式卡的插图从内联 SVG 换成了真实照片**（`assets/couple/tongcheng.jpg` / `yidi.jpg`，720px 宽，`object-fit: cover`）。照片底下压一层同色渐变 `veil`，图片没加载完或深色模式下都不会露出一块白；插图仍包在 `<button>` 里，但点击统一走 `bindOnboarding` 的事件委托——真机上手指落在图片上时，合成 click 不会冒泡到 button
- **返回按钮做成气泡**：`data-cp="mode-back"` 这类子页返回键是一个 34×34 的圆角气泡，18×18 的 chevron 图标用 flex 居中（实测图标中心与按钮中心偏差 0px），不再写「返回」两个字
- **禁止 `[data-close]` 这类不存在的选择器**：弹层关闭按钮的真实 class 是 `.sheet-close`，早期测试批量用了不存在的 `[data-close]`，全部静默失效、弹层叠着没关，看着像「点了没反应」
- **不能假设 `summary().byAccount` 是数组**：它是对象 map，`byAccountList` 才是排好序的数组
- **`openSheet` 的 `onMount` 是同步调用的**：写成 `const sheet = UI.openSheet({ onMount(){ mount(body, close, sheet) } })` 会撞 TDZ（`Cannot access 'sheet' before initialization`），整个 `onMount` 静默死掉
- **`renderOnboarding` 的分支顺序决定「按钮点了有没有反应」**：旧代码把 `if (!hasBook && (step === 'consent' || ...)) step = 'intro'` 写在最前面，首次开通时 `hasBook` 恒为 0，`step = 'consent'` 当场被打回 `'intro'`——点「去同意」页面纹丝不动。现在判据是 `step !== 'intro' && !hasBook && hadBookBefore && !canResume`，用 `deletedAt`（`wipeCpBook` 写）/ `closedAt`（关闭写）区分「从来没建过」和「删光了」
- **`addGoal` 必须给情侣基金盖 `cpBookId`**：`coupleGoals / goalBySlot / coupleDateFund / coupleMeetFund / coupleVault` 全都按 `g.cpBookId === cpActiveId()` 过滤，漏写这一行的表现是「点了建基金，回头还是『还没设目标』」
- **事件去抖要按元素而不是按时间**：`fire()` 原来只比 `Date.now() - lastAct < 350`，真机连点两个不同按钮时第二个会被吞掉，看起来就是「点了没反应」。现在多存一个 `lastEl`，只有同一个元素连点才去抖
- **`checkMeetFundFull` 要按「谁刚刚攒满」挑目标**：不能直接拿 `coupleMeetFund()`，否则用户在实际存的是小金库、而见面基金恰好存在却没设目标时，永远弹不出提示
- **偏爱清单必须排掉退款记录（`refundOf`）**：账单页早就这么做了，`favorList()` 漏了这一条 —— 红包退 20 之后清单会多出一条「TA 又给了你 ¥20」的假行，52 变 72，而且合计跟月报对不上。现在两处口径统一：退款只在原红包的净额里体现
- **偏爱合计一律走 `S.cpNetOf`（净额）**：首页卡、偏爱页合计、行内金额以前都用 `t.amount` 毛额，退过款之后首页写「TA 一共给你 ¥100」、月报和账单只算 ¥60。退款行还会带一句「已退 ¥X」，让数字来历看得见
- **Windows 上 `proc.kill()` 杀不掉 Edge 的整棵树**：渲染/GPU 子进程还活着，profile 目录的文件被攥着，`rmSync` 直接 EPERM，异常被吞掉后每轮回归在 `%TEMP%` 里留几十 MB（实测 298MB）。现在 `_env.stop()` 走 `taskkill /T /F` + 等句柄释放 + 重试删除，`sweep()` 的阈值也从 1 小时降到 15 分钟并额外清理「建它的进程已经没了」的目录
- **测试的「假绿」比失败更贵**：`verify-favor-add` 曾把「打印计数 + `process.exit`」写在 `finally` 里，中途点了个早已删除的按钮抛异常，9 条断言只跑 5 条还报「通过 5/5」、退出码 0。现在所有断言跑完才汇总、异常一律退 1；`run-all` 也把子进程退出码纳入判定，光看「通过 N / N」不再算数
- **截图不要落在源码树**：`shoot-*.js` / `art-*.js` 原来全写 `_test/shots`，一轮跑屏几十 MB 的 PNG。现在统一走 `env.shots('<套件名>')` 落在系统临时目录，`node _test/clean-shots.js` 可一键回收历史残留
